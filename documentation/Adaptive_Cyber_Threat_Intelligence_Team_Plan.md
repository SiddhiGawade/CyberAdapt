# Adaptive Cyber Threat Intelligence under Concept Drift

## 1. Project Concept

**Goal:** Build an adaptive intrusion-detection system that analyzes network-flow traffic, detects concept drift when traffic behavior changes, and adapts/updates the model using recent data.

### Practical Demonstration

Instead of monitoring a large production website such as Amazon, use an **existing web application/project** owned by the team as the controlled environment.

```text
Existing Web Application
        ↓
Network Traffic / Flow Data
        ↓
Flow Feature Extraction
        ↓
Initial ML-Based IDS
        ↓
Chronological Windows
        ↓
Concept Drift Detection
        ↓
Drift Detected?
   ↓ No        ↓ Yes
Continue    Adapt/Update Model
   ↓             ↓
   └──────→ Updated Model
                  ↓
          Performance Comparison
          + Explainability
          + Dashboard
```

The website is mainly the **traffic-generating/test environment**. The ML system operates as a monitoring and adaptation layer.

---

## 2. Demonstration Scenario

### Stage 1 — Normal Traffic
- Collect normal traffic generated by the existing website.
- Extract network-flow features.
- Train the initial IDS model.

### Stage 2 — Controlled Abnormal Traffic
- Generate **authorized, controlled test traffic** against the team's own environment.
- This changes the traffic distribution.

### Stage 3 — Drift Detection
- Process traffic in chronological/sliding windows.
- Monitor model behavior and traffic distribution.
- Detect concept drift.

### Stage 4 — Adaptation
- When drift is detected, use recent traffic data to update/retrain the model.
- Produce an updated model.

### Stage 5 — Evaluation
Compare the model before and after adaptation using:
- Accuracy
- Precision
- Recall
- F1-score
- Confusion matrix
- Performance over time
- Drift points
- Number of adaptations

The core project objective is to show that the model can continue handling changed traffic behavior rather than remaining a fixed train-once model.

# 3. Team of 4 — Recommended Distribution

| Member | Responsibility | Main Deliverables |
|---|---|---|
| **Member 1** | Data Pipeline + Traffic Collection | `preprocessing.py`, processed datasets, flow/traffic collection |
| **Member 2** | Baseline IDS / ML Model | `baseline_model.py`, trained model |
| **Member 3** | Concept Drift + Model Adaptation | `drift_detection.py`, `adaptation.py` |
| **Member 4** | Evaluation + Explainability + Dashboard | `evaluation.py`, XAI module, Streamlit dashboard |

### Member 1 — Data Pipeline
- Select and prepare network-flow data.
- Collect/organize traffic from the existing website.
- Clean data.
- Handle missing/categorical values.
- Encode labels.
- Feature selection/scaling where required.
- Create chronological train/validation/test/stream data.
- Provide a standard data-loading interface.

### Member 2 — Baseline IDS
- Train the initial intrusion-detection model.
- Start with a manageable baseline such as Random Forest.
- Implement prediction and evaluation.
- Save the trained model.
- Provide standard functions such as:
  - `train_model()`
  - `predict()`
  - `evaluate_model()`

### Member 3 — Drift + Adaptation
- Implement chronological/sliding-window processing.
- Implement concept-drift detection.
- Evaluate candidate detectors such as ADWIN, DDM, Page-Hinkley or a suitable statistical approach.
- Trigger adaptation when drift occurs.
- Implement model update/retraining using recent traffic.
- Provide:
  - `detect_drift()`
  - `adapt_model()`

### Member 4 — Evaluation + Dashboard
- Build before/after adaptation comparisons.
- Generate confusion matrix and performance graphs.
- Visualize drift points and model updates.
- Add explainability/feature importance.
- Build a Streamlit dashboard.
- Initially use dummy data so dashboard development can happen in parallel.

# 7. Final Demo Story

> We use an existing web application as a controlled environment. Initially, the system observes normal network traffic and trains an intrusion-detection model. We then introduce controlled abnormal traffic scenarios within our own environment. The system processes traffic chronologically, detects changes in traffic behavior as concept drift, and adapts the model using recent data. Finally, we compare detection performance before and after adaptation to demonstrate whether the updated model handles the changed traffic more effectively.

## 9. Research Alignment

The project is based on the reviewed literature's common direction: stream learning, adaptive classifiers, concept-drift detection, incremental learning, sliding-window analysis and active learning. The assignment's stated project objective is to analyze chronological network-flow records, classify normal/malicious traffic, detect concept drift, adapt/retrain using recent data, and compare performance before and after adaptation.
